# TTD-DR
Deep Researcher with Test-Time Diffusion

## 开源复现
1. 当前版版:使用react 流程 + Tool
2. 存在明显缺点: 
   * 没法在调用生成子问题Fc的时候，把草稿、研究计划、之前轮数据塞进去。只是通过提示词指导在通过上下文生成gaps_query.
   * 研究计划、草稿、修订 入参和出参差不多，重复。
   * 这个是纯粹的固定流程，使用langgraph更合适。
   * 单个react上下文不足，并行搜一次(4个子查询)就阻塞住了。最终输出必然长度不足。
3. 实现起来，迭代搜索子问题基本上很多开源项目都是这样做的。但是第一次遇到草稿，在最初就生成草稿，然后在流中传递。
这样主观感觉还行。之前做的，都是前面的流程都是搜索，尽可能搜到足够正确的上下文，提供给最后一步的报告生成。
4. 组件级自我进化: 在搜索后，只对答案进行评价反馈，感觉效果不会很大，毕竟上下文是不变的。
